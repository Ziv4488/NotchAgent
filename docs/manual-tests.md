# 手动测试清单

自动化测试覆盖不到的部分：窗口层级、屏幕几何变化、焦点归属、跨 Space 行为。
每次动到 `NotchWindow` / `NotchHostingView` / `IslandWindowController` 都要过一遍。

跑之前先起 app：

```sh
xcodebuild -project NotchAgent/NotchAgent.xcodeproj -scheme NotchAgent -configuration Debug build
open ~/Library/Developer/Xcode/DerivedData/NotchAgent-*/Build/Products/Debug/NotchAgent.app
```

两个调试入口，**性质完全不同**：

| 参数 | 走什么 |
|---|---|
| `--args -debugState running\|notice\|expanded\|newtask` | **假数据**，不接会话层。用来验形态、动画、拖拽 |
| `--args -debugTask <目录> -debugPrompt "<指令>"` | **真链路**：真起 `claude`、真接 hook。用来验第 10 节起的内容 |

其余状态跃迁走**菜单栏图标**里的调试菜单（只在 `-debugState` 下有意义）。

> 菜单栏图标长得像一个刘海矩形，在你那排状态图标的**最左边**。
> 注意：第三方状态项在 `CGWindowListCopyWindowInfo` 里由「控制中心」统一合成、
> 报成匿名的 `Item-0`，所以别靠窗口列表找它——要开关 app 数个数。

## 1. 窗口层级与命中

岛的画布是**这块屏幕上岛能达到的最大尺寸**的透明窗口（本机约 1352×835），压在屏幕顶部中央，
状态切换和拖拽都不改它。岛本身只占其中一小块，**其余全是透明区**。
所以命中测试收回岛的轮廓是**必需的**，不是优化 —— 一旦失效，屏幕上半部的点击会被整片吞掉。

| # | 操作 | 期望 |
|---|---|---|
| 1.1 | 看 idle 态 | 岛比刘海宽出左右各 80pt，上沿两侧内凹拐角、底部圆角。**四周不该有任何描边或黑雾**——岛的边缘和桌面之间是硬边界 |
| 1.2 | **idle 态下**，点岛正下方的桌面／窗口（大约屏幕正中偏上那片） | 点击**穿透**，落到下面的 app 上。这块是透明画布，绝不能吞点击 |
| 1.3 | **idle 态下**，点菜单栏最左边的「NotchAgent / 文件」等菜单 | 菜单正常打开。岛 345pt 宽，左边缘在 583pt，盖不到那里 |
| 1.4 | 展开态下点菜单栏 | 岛此时 560pt 宽，**会**盖住中间那段菜单栏，这是设计如此。只要没被盖住的部分能点就算过 |
| 1.5 | 点控制中心 / 时钟 | 正常展开 |
| 1.6 | 悬停在岛上 | 只有轻微提亮，**不展开、不预览** |
| 1.7 | 展开态，把窗口挪到岛正后方，观察岛的四周 | 岛外**没有**渐变暗环。曾经有一圈 12pt 投影，落在透明画布上是洗不掉的黑雾 |

## 2. 焦点（spec 11.2 的四个条件）

| # | 操作 | 期望 |
|---|---|---|
| 2.1 | 在别的 app 里打字，然后点岛展开 | 岛拿到焦点、**光标直接就位**，不用再点一下；前一个 app 失焦（和 Spotlight 一样）。`NSApp.activate()` 是异步的，焦点要抢两次才稳。**有活会话时光标在终端里**（Claude Code 自己的 `❯`），没有活会话时在岛的输入框里 |
| 2.2 | 在展开的岛里打字 | 字进当前那个光标所在的地方 |
| 2.2b | **点一下 tab 芯片、模式芯片、✕** | 全都有反应。拖拽手柄那层是盖在整个岛上的，若没显式放行点击会把这些全挡掉，表现和「光标没激活」难以区分 |
| 2.3 | 切中文输入法在终端里打字 | 候选框浮在岛**之上**，不被挡；上屏的中文正确进入 Claude Code 的输入框 |
| 2.4 | 按 `⌘W` | 岛收起，焦点回到 2.1 里那个 app |
| 2.4b | 新建表单里按 `Esc` | 退出新建流程。此时 first responder 是岛的输入框，没有终端在接键 |
| 2.4c | **焦点在 A 时展开岛 → 点去 B → 收起岛** | 焦点**留在 B**。不该被弹回 A —— 展开期间用户自己选的窗口不能被收起动作撤销 |
| 2.4d | 上一条不对时想确诊 | `log show --last 5m --info --predicate 'subsystem == "com.notchagent" AND category == "focus"'`。三行话：展开记下了谁、谁抢过前台、收起还给了谁 |
| 2.4e | 岛开着，去点别的 app（岛失去焦点），再回来点岛里的东西 | **一下就成**：那一下点击既把键盘拿回来，也照常作用在你点的那个东西上。不许要「先点一下把焦点切回岛、再点第二下才管用」 |
| 2.4f | 接上一条，之后收起岛 | 焦点回到你**刚才**那个 app（点回岛之前待的那个） |
| 2.5 | idle / running / notice 三态 | 全程不抢焦点，别的 app 打字不受影响。唯一的例外见 14.14b（浮层里那个输入框，而且要你点它才拿） |

## 4. Space 与全屏

进出全屏、切 Space 都有约一秒动画，通知到达时窗口尺寸还没稳定。
任何环境变动之后都会每 0.5 秒复查一次、持续 3 秒，藏起来期间则一直复查。
所以「该消失的没消失 / 该回来的没回来」最多等一秒，**超过就是 bug**。

| # | 操作 | 期望 |
|---|---|---|
| 4.1 | 切到另一个（非全屏）Space | 岛跟随，每个 Space 都在 |
| 4.2 | 把某个 app 切全屏 | 岛消失（刘海区被系统占用，spec 3.4）。**只有全屏才消失**，普通最大化不算 |
| 4.3 | 退出全屏 | 岛在一秒内自己回来，不需要点任何地方 |
| 4.4 | 全屏 app 与普通 Space 之间来回切 | 岛跟着消失/恢复，不残留 |
| 4.5 | **把岛展开着**，再切到全屏 app 的 Space | 岛**先收起再消失**。展开态是抢着焦点的，只 orderOut 会留下一个看不见却仍是 key 的窗口，键盘继续进岛 |
| 4.6 | 从全屏 Space 切回来 | 岛以收起态回来（不会替你恢复成展开），焦点在你原来那个 app 上 |

## 6. 状态带（左右分区与状态形态）

状态带最容易出的两类错：文字跑进物理刘海底下，和折成两行。

| # | 操作 | 期望 |
|---|---|---|
| 6.1 | 一个会话都没有时看 idle | 左侧只有 `NotchAgent` 一行，**不折行**；右侧空 |
| 6.2 | 新建两个假会话 | 左侧：状态点 + 会话名（超长截断成 `refactor-a…`）；在跑时改为显示「在干什么」；右侧：本轮计时 + 会话数 |
| 6.3 | 盯住左右两侧的文字边界 | 左侧文字**在刘海左边缘之前就结束**，右侧文字**在刘海右边缘之后才开始**。任何一侧压到刘海底下都是 bug |
| 6.4 | 让计时跑一会儿 | 每秒跳一次；过一小时补上小时位 |
| 6.5 | 看「在跑」的状态点 | 琥珀色，约 1.1 秒一次**慢呼吸** |
| 6.6 | 调试菜单「最早的会话开始问你」 | 该会话转「等你回话」：状态点变**蓝色、约 0.55 秒一次快闪**，tab 角标变蓝色问号，岛进入 `notice` |
| 6.7 | 再「完成最早的会话」 | 绿色、不闪 |
| 6.8 | 「清空会话」后看 idle | 回到 6.1 |

## 8. 拖拽调整尺寸（展开态）

拖动时**承载岛的窗口一动不动**（它一开就是最大尺寸），只有岛在里面变形。
所以任何闪烁、抖动、岛偏离屏幕中线，都是 bug。

| # | 操作 | 期望 |
|---|---|---|
| 8.1 | 展开后看边缘 | 只有底边中央一条短横条。**两个下角不该有任何标记** —— 岛的下角是圆角、贴着桌面，画直角线读起来像「岛外面还套了个框」 |
| 8.2 | 鼠标扫过**左右两条竖边** | 光标变左右箭头。这里必须有反应 —— 调整窗口的直觉就是抓侧边 |
| 8.3 | 鼠标移到底边中段 / 两个下角 | 分别变上下箭头 / 斜向箭头（macOS 15+）。**移开后光标必须变回来**，卡住不还原是 bug |
| 8.4 | 拖左侧竖边往左 | 岛左右**对称**变宽，高度不变 |
| 8.5 | 拖底边中段往下 | 只有内容区变高，tab 条 / 输入框高度不变 |
| 8.5b | 会话从「在跑」变成「已结束」 | 岛的**总高度一点都不变**。输入框那 44pt 是由内容区吸收的，会话状态一变岛就抽搐一下是 bug |
| 8.6 | 拖右下角往右下 | 同时变宽变高 |
| 8.7 | 快速来回猛拖任意手柄 | **全程不闪、不抖**，岛始终跟手 |
| 8.8 | 拖右下角往右拖到底，再拖左下角往左拖到底 | 岛**始终居中于屏幕中线**，绝不会整块跑偏。宽度停在上限 |
| 8.9 | 一直往里拖到底 | 停在下限（宽 420pt），内容仍排得下 |
| 8.10 | 收起再展开 | 记住刚才拖出来的尺寸 |

> 尺寸存在 `UserDefaults`，重启后恢复（第 12.4 条）。

## 10. 真实会话（第 2 阶段）

先跑一遍自动的：

```sh
./scripts/smoke.sh      # 起真 claude，断言 hook 事件真的到了岛这边
```

然后手动：

| # | 操作 | 期望 |
|---|---|---|
| 10.1 | 点 ＋ → 选一个项目 → 敲指令回车 | 岛里出现真的 Claude Code TUI（欢迎框、`❯` 提示符），并**自动带着你那条指令跑起来** |
| 10.2 | 在终端里直接打字 | 字进 Claude Code 自己的输入框。**这里没有岛的输入框** —— 有活会话时键盘整个归终端 |
| 10.3 | 打 `/` | Claude Code 的斜杠命令菜单正常弹出、上下键能选 |
| 10.4 | 让它做一件要权限的事（比如写 cwd 之外的文件） | 终端里弹出「Do you want to…」选单，**敲 `1` / `2` / `3` 直接生效**。岛这边同时转「等你回话」（蓝点快闪）并进 notice |
| 10.4b | 接上条：**点岛展开**（不点 tab）→ 在终端里选「不允许」→ 收起岛 | 岛回到 idle。**不能一直挂在 notice** —— 通知弹出来时那个 tab 本来就是选中的，用户根本不会去点 tab，所以「点岛」这条路必须也算已读 |
| 10.5 | 按 `Esc` | 当前这一轮停下，会话还在，可以接着说话。**岛不再拦这个键** |
| 10.5b | 在 Claude Code 的选单里按 `Esc` | 选单关掉（屏幕上印的「Esc to cancel」是真的），**岛不收起** |
| 10.5c | 连按两下 `Esc` | 进入 Claude Code 的历史回退，岛全程不插手 |
| 10.5d | 在终端里按 `⌘W` | **岛收起**，终端里什么都没发生 |
| 10.6 | 拖岛的右下角变大 | 终端**重新排版**跟上新宽度（Claude Code 的框线、表格不会错位） |
| 10.7 | 找不到 `claude` 时（可临时把它改名试） | 新建表单上原地出现红字「找不到 claude 命令…」，**不会建出一个空 tab** |
| 10.7b | 旧 tab 点「继续上次会话」，在「选哪个 session」那一屏按 `Esc` | claude 当场退出，岛上给的是**「会话已结束 · 继续上次会话」**那块面板。不许留一整块黑（进程死了，Claude Code 退出时还原了备用屏，画出来只有左上角一个光标，看着像卡住） |
| 10.8 | 看终端右边那条内沿 | 正文一直排到右边框，**不许留一条竖着的空条**。SwiftTerm 无条件给 `NSScroller` 留位置（`reservedScrollerWidth`），包里没人去藏它 —— 我们在 `ObservingTerminalView` 里藏掉。同样宽度下藏掉能多排 **2 列**（滚动条占 15pt ÷ 12pt 的格宽 7.4pt）。<br>（早先记的「82 列 / 79 列」那对数是**字号还是 11pt、岛还被拖宽过**时量的，绝对列数跟着岛宽和字号走，别拿它当固定值） |
| 10.9 | 看终端底色，和岛体（状态带、tab 条那一圈）比 | 终端那张卡是 **#1E1E1E**，比岛体**明显浅一档**；岛体仍是纯黑。旧值是半透明白叠在黑上 = #0B0B0B，几乎纯黑，亮字打上去久了眼睛发涩。底下的输入框跟终端**同色**，靠 0.5pt 描边区分，不许比终端暗（那样看着像卡片下面破了个洞） |
| 10.10 | 会话活着时看终端卡片的**下沿** | 卡片下面留 **8pt 黑边**（和左右那 7pt 一起，岛四边都有框）。一度做成过卡片铺到岛下沿、下角跟着岛走 —— 方向是错的，用户的原话是「我对月牙没有意见，我需要看起来是整个岛，而不是终端下方跟岛外的内容没有边界」。顶到底之后岛的下沿就成了正文的边，桌面从字底下开始 |
| 10.10b | **新建流程**（点 ＋，尤其是选完目录之后）看下沿 | 同上。这张表单和终端共用一张卡（`PanelCard`），一样留 8pt |
| 10.10c | 会话结束、下面的输入框回来之后再看下沿 | 黑边**一样宽**（那时候是输入框自己的 `.padding(.bottom, 8)` 在留），岛的下边框不该忽宽忽窄 |
| 10.10d | 盯着**下面两个角**看：卡片的弧和岛的弧 | 两条弧**处处平行**，转角处的黑边和直边一样宽。卡片半径 = 岛的半径 − 内缩 = 12 − 7 = **5**（`PanelCard.cardRadius`，算出来的不是写死的）。写死 10pt 时卡片比同心该有的圆，转角黑边比直边宽出一截，用户报的「岛的圆角需与终端的圆角保持一致」就是这个 |
| 10.11 | 在终端的输入框里打一行字，按 **⌘←**，再打一个字 | 那个字落在**行首**。⌘→ 同理落在行尾。终端本身没有「行首」，这一下是被翻译成 Claude Code 认的 `Ctrl+A` / `Ctrl+E` 送进 PTY 的 |
| 10.11b | 按 **⌘⌫** | **整行删掉**（翻译成 `Ctrl+U`） |
| 10.11c | 按 **⌥⌫** | 删掉**前一个词**（翻译成 `Ctrl+W`）。这条不是锦上添花：不翻的话 SwiftTerm 发的是 `ESC` + `0x08` 两段，Ink 一段当一次按键，于是 Claude Code 先收到一个孤零零的 **Esc** —— 那是「掐掉这一轮」，岛这边也会跟着把 tab 判成「用户取消了」 |
| 10.11d | **按着 ⇧ 按左右方向键** | 光标照常左右移动（⇧ 被吃掉了）。**选中做不到** —— Ink 的输入框没有选区这个概念。但实测原样放行的话 ⇧← 一个字节都进不了 PTY，连移动都废掉，那更糟 |
| 10.11e | 选一段终端里的文字（鼠标拖），按 **⌘C**；再到输入框按 **⌘V** | 复制的**只有选中那一段**，粘贴进去的也只有那一段。**⌘A** 全选整屏。岛是 `LSUIElement`、没有主菜单，这三个动作本来一路无人认领 —— 现在由终端视图直接接管 |
| 10.11f | **先按一次 ⌘A**，再点一下终端里别处（选区消失），然后按 **⌘C**，去别处 ⌘V | 贴出来的是**你上一次自己复制的东西**，不是整屏。SwiftTerm 的 `copy(_:)` 不看 `selection.active`，而 `selectNone()` 只置 false、**不清 start/end** —— 于是按过一次 ⌘A 之后，⌘C 会一直把那一整片再交出去，用户报的「⌘C 把整个对话复制了、⌘V 整段贴进去」就是这个 |
| 10.11g | 什么都没选，直接按 **⌘C**，再去别处 ⌘V | 剪贴板**原封不动**。`copy(_:)` 会无条件 `clearContents()`，实测能把剪贴板清成空串 |

> ### 岛的终端和真终端不一样的地方
>
> 「交互和真终端一模一样」是硬要求，所以每一处偏离都得是**刻意的**，都记在这里：
>
> | 处 | 岛里 | 真终端里 | 为什么 |
> |---|---|---|---|
> | `⌘W` | 收起岛 | 关标签页 | 岛得有个收起的键，而 Esc / ⇧Tab 都被 Claude Code 占着（§10.5） |
> | `⌘←` `⌘→` `⌘⌫` | 翻成 `Ctrl+A` / `Ctrl+E` / `Ctrl+U` | 多数终端什么都不发 | macOS 的手势，用户就是这么按的 |
> | `⌥⌫` | 翻成 `Ctrl+W` | 发 `ESC` + `0x08` 两段 | 两段进 Ink 会被当成「Esc 然后退格」，Esc 在这儿是掐掉这一轮 |
> | `⇧←` `⇧→` | 当成普通方向键 | 发带修饰位的序列 | Ink 没有选区；而 SwiftTerm 干脆一个字节都不发，连移动都废掉 |
> | `⌘C` `⌘V` `⌘A` | 终端视图直接接管 | 由「编辑」菜单派发 | 岛是 `LSUIElement`，压根没有主菜单 |
> | `⌘C` 且没有选区 | 什么都不做 | 什么都不做 | **这条是为了对齐才写的代码**：SwiftTerm 自带的 `copy(_:)` 会清空剪贴板、或者把上一次的旧选区交出去（§10.11f/g） |
> | 右边的滚动条 | 藏掉了 | 有 | 见 §10.8，那 15pt 白占一列 |
> | 收起态浮层里的输入框 | 字先攒在岛上，回车才整段进 PTY | 逐字进 | 中文输入法组字期间每一下都会被当成正文送出去（§14.14c） |
>
> 其余一律原样：`Esc`、`⇧Tab`、`Ctrl-*`、`⌥←/⌥→`、方向键、回车、中文输入法，
> 全部直通 PTY，岛不插手。

| 13.16 | 一个排在最左边的老 tab，点「继续上次会话」 | 重开之后**还在最左边**，名字也还是你改过的那个 |

> **「拖动的时候会抽动，不跟手」**：两处叠在一起。
> 一是岛的形变动画原本挂在 `model.tabs` 上，换位也算 tabs 变了，整条 tab 条
> 跟着弹 0.38 秒的簧；现在挂在 `IslandModel.tabShape`（几个、多宽）上，与顺序无关。
> 二是 `DragGesture` 默认用**芯片自己的**局部坐标系，而换位之后芯片挪了一格、
> 局部原点跟着挪，`translation` 当场跳一整格 —— 换过去、跳回来、再换过去。
> 改成 `.global` 之后位移才是手真的走了多远。

> **「每个标签之间切换反应都很慢」**：原本 tab 芯片上叠着两条手势 ——
> `.onTapGesture(count: 2)`（改名）和 `.onTapGesture`（切换）。它们是互斥关系，
> 单击必须先等满系统的双击间隔、确认没有第二下才轮得到它。
> 实机量过：**点下去到 tab 真的切过去 363 ms**。换成 `.simultaneousGesture` 也没用
> （又量了一次，还是 363 ms）—— 只要存在一条 `count: 2` 的手势，单击就得等。
> 现在只留一条单击手势，双击由 `TabStrip.tapped(_:)` 按 `NSEvent.doubleClickInterval`
> 自己数。同一处再量：**4 ms**。

> **「点了 Type something 就卡住」**：那两项选中之后终端就不是在让你选了，而是在
> 等一段自由输入。收起态**没有键盘焦点**（窗口只有展开时才能成为 key），于是打字
> 没反应；更糟的是浮层还摆着，再点别的选项，数字全打进了那个输入框 ——
> 用户实机上打出过「55534」。
>
> 认的办法是页脚。实测（`scripts/spike-textentry.py`）：
> `Enter to select · ↑/↓ to navigate · Esc to cancel`
> → `Enter to select · ↑/↓ to navigate · ctrl+g to edit in Vim · Esc to cancel`。
> **前半截没变**，所以只能认那句 Vim 提示。
>
> 认出来之后**第一版是把岛展开**（键盘归终端）。用户不要：「不能不打开在直接在
> 上面输入吗？」现在浮层自己换成一个输入框，`canBecomeKey` 在这段时间里额外
> 放行（`IslandModel.wantsInlineTextEntry`），点一下框就能打字。**框不主动抢焦点**
> —— 它可能在你正于别处打字时冒出来。
>
> 回车那一下**必须和正文分两次写、中间隔开**。实机验过两次：`"noodles\r"` 一次
> 写进 PTY，终端收到的是 `→ __other__`（空的自定义回答），正文整段丢了 ——
> Claude Code 的 TUI 是 Ink 写的，它把一次 stdin chunk 当成**一次按键**。
> 分开之后同一条路上收到的是 `晚饭吃什么？ → noodles`。
>
> 这里还带出一个更要命的洞：**收起态下岛里的终端只有六十出头列，长页脚会折行**：
> ```
> Enter to select · ↑/↓ to navigate · ctrl+g to edit in Vim · Esc
> to cancel
> ```
> 没有任何**一行**含「Esc to cancel」，`parse` 一路返回 nil。页脚现在连着下一行
> 一起看。两份样本都在 `Fixtures/screens/`（展开态一行的、收起态折行的），
> 都是真跑出来、经 `visibleLines()` 取的。

> **「选项点不动」是怎么回事**：画布是整块最大态尺寸的透明窗口，命中测试收在岛的
> 轮廓里（`NotchHostingView`），浮层挂在轮廓之外，得靠 `model.menuFrame` 单独放行。
> 那个矩形之前一直是 `.zero`：位置本来是用 `PreferenceKey` 报上去的，而 `.background`
> 里的 `preference(key:value:)` 根本传不到 `onPreferenceChange`。矩形是空的，
> 命中测试就一律拒绝 —— 点在浮层上和点在空气上没有区别。
>
> 现在量完直接写回 model。坐标空间的名字也挪了位置：原先挂在里层的 VStack 上，
> 原点是 VStack 的左上角，而 VStack 只有岛那么宽、在画布里居中 —— 报上去的 x
> 比真实位置小了半个画布（实测差 488pt）。两处都由
> `NotchHostingViewTests` 里那组浮层测试钉着。
>
> 整条路在实机上验过：合成一次真正的 AppKit 点击打在第 1 项上 →
> `IslandModel.choose` → `1` 进 PTY → 终端里出现
> `User answered Claude's questions: 晚饭吃什么？ → 面食`。顺带确认一件事：
> 这类选单页脚虽然写着 `Enter to select`，**数字键是直接选中的**。

> **为什么 Esc 要单独认**：探针实测（`scripts/spike-escape.py`），按 Esc 之后
> Claude Code **一个 hook 都不发** —— `PostToolUse` 没有、`Stop` 没有，等 25 秒也没有。
> 而选单一消失，岛原本按「答完了」把状态交回「在跑」，于是那个 tab 永远琥珀色
> 慢呼吸、计时一路往上涨。
>
> 认的办法是看**用户自己按下的那个键**：所有打进 PTY 的字节都经过我们的视图
> （`ObservingTerminalView`），Esc 在 Claude Code 里的含义是明确的 ——「停下这一轮」。
> 这跟它的界面文案、跟它哪个版本都无关。屏幕上那句 `User declined to answer questions`
> 也能认，但那是会随版本变的英文句子。
>
> 顺带纠正一句之前写在 14.2 的话：`AskUserQuestion` **会**发 `PreToolUse`，
> 而且 payload 里带着完整的问题和选项。它不发的是 `Notification` ——
> 也就是没有任何事件说「它停下来等你了」，岛光靠 hook 会一直显示「在跑」。
> 这才是屏幕这条通道存在的理由。

> **怎么认出来的**：从 SwiftTerm 渲染完的屏幕缓冲区里扒（`CLISession.visibleLines`），
> 半秒扫一次，连着两拍结果一样才算数 —— 选单是一行行画出来的，扫在半中间会读到
> 一个选项不全的版本。认不出来一律当没有：Claude Code 每次升级都可能改这些字，
> 显示半个错的选单比不显示危险得多，用户会照着它按键。
>
> 两份判定样本（`Fixtures/screens/`）都是跑真的 claude、经同一个 `visibleLines()`

## 12. 持久化与退出

| # | 操作 | 期望 |
|---|---|---|
| 12.1 | 有任务在跑时退出 app | 弹确认框「还有任务在跑」。**取消**则 app 不退 |
| 12.1f | **关一个还在跑的 tab**（点 tab 上的 ×） | 弹确认框「『<标题>』还在跑」。**取消**则 tab 原封不动、进程照跑。和退 app 的确认是同一件事的两个尺度 |
| 12.1g | 关一个**已经结束**的 tab（显示「继续上次会话」那种） | **不弹框**，直接关。那一下没有代价，`--resume` 还接得回去 |
| 12.1c | 确认退出之后，`ps -ef \| grep island-hooks.json` | **一个都不剩。** 两道保险：岛自己的子进程随 PTY 关闭拿 SIGHUP；跑到岛外面去的那些由 `SessionReaper` 按 `--settings <岛自己那份>` 扫出来 SIGTERM（还赖着的补 SIGKILL）。2026-08-02 实机验过：四个残留会话在岛退出后全部收掉 |
| 12.1d | 关一个 tab 之后，`ps -ef \| grep <那个会话的 session-id>` | 也是一个都不剩。关单个 tab 走的是 `--session-id <UUID>` 那条特征，只收这一个会话 |
| 12.1e | 在终端里自己跑一个 `claude`（不经过岛），然后退出岛 | 你自己那个**不受影响**。认人只认岛自己那份 `--settings` 的绝对路径，用户手动跑的不会带 |
| 12.1b | **展开态**下、有任务在跑时退出 | 确认框**看得见**。它压在岛上面，不是被岛盖住 |
| 12.2 | 确认退出，再重新打开 | tab 还在，显示为已结束态；内容区是「继续上次会话」卡片 |
| 12.3 | 点「继续上次会话」 | 在同一目录起 `claude --resume`，能接上历史 |
| 12.4 | 拖大岛 → 退出 → 重开 | 尺寸记住了 |
| 12.5 | 手动把 `~/Library/Application Support/NotchAgent/tabs.json` 改坏，重开 | tab 条是空的，**app 照常启动**，不崩 |

> **12.1b 是实机抓出来的一个「看起来像死机」的 bug。** 岛压在 `statusBar + 1`（26），
> `NSAlert` 是 `.modalPanel`（8），展开态的画布又有 1368×835 那么大 ——
> 确认框正好整个落在岛底下：`layer=26 bounds=72,0 1368x835` 盖着
> `layer=8 bounds=626,200 260x235`。
>
> 那时候 app 并没有崩，它停在 `runModal()` 里等一个**看不见的**按钮：
> 界面全无反应、菜单栏点退出也没用（已经在模态循环里了），只能去活动监视器强杀。
> 修法和文件选择框一样 —— 让岛下去（`NotchWindow.steppingAside`），
> 抬高弹框是行不通的，`runModal()` 里会被 AppKit 重置。

## 12b. 第一次用（换一台机器、换一个目录）

岛**不管 Claude Code 的登录**，也不复制一份配置。它做的只有两件事：
在登录 shell 的 PATH 里找到 `claude`（`ClaudeLocator`），然后在伪终端里把它起起来。
认证、模型、`~/.claude/settings.json` 全都沿用你自己那一份 ——
所以在一台已经用过 Claude Code 的机器上，**你不会觉得有「要开 claude」这一步**，
那一步早就在你自己的终端里做完了。这不是配置时省掉了什么。

换句话说，下面这些门槛是 Claude Code 自己的，岛只负责把它们**如实显示出来**，
不代答、不跳过。它们只有在干净环境里才会出现，容易漏测：

| # | 操作 | 期望 |
|---|---|---|
| 12b.1 | 在一个**从没用过的目录**里起会话 | Claude Code 先问「Is this a project you created or one you trust?」，1/2 两个选项。岛把这个 tab 标成**等你回话**（蓝点 + `?` 角标），不是「在跑」 |
| 12b.2 | 同上，在收起态 | 岛下方浮出选项面板（第 14 节的通道）。这道题的页脚同样是 `Esc to cancel` |
| 12b.3 | 在一个**没登录过**的账号 / 环境里起会话 | `claude` 自己的登录流程原样出现在岛里的终端。岛不该显示成「在跑」，也不该自己弹任何登录界面 |
| 12b.4 | 登录过期 | 同上：它自己怎么提示，岛里就怎么显示 |
| 12b.5 | 根本没装 `claude` | 见 10.7：新建表单上红字提示，**不建空 tab** |

> 12b.1 已实测（截图在案）：全新目录确实被信任确认挡着，岛标成了「等你回话」。
> 12b.3 / 12b.4 需要一个没登录的环境，我这边没有 —— 留给你。

## 13. 不该发生的事

| # | 检查 | 期望 |
|---|---|---|
| 13.1 | 看 `~/.claude/settings.json` | **一个字都没被改过**。岛走的是 `--settings`，与用户设置合并 |
| 13.2 | 看 `~/Library/Application Support/NotchAgent/island-hooks.json` | 顶层**只有 `hooks` 一个键**。多一个键就会顶掉你自己设置里的同名项 |
| 13.3 | 项目里本来就有 `.claude/settings.json` 的 hooks | 你的 hook 和岛的 hook **同时**触发，谁也没被顶掉 |
| 13.4 | 岛没开着时在终端里干活 | 每次工具调用都会跑一次转发命令，**感觉不到任何卡顿**（实测连不上时 25ms 内退出） |
