# 手动测试清单

自动化测试覆盖不到的部分：窗口层级、屏幕几何变化、焦点归属、跨 Space 行为。
每次动到 `NotchWindow` / `NotchHostingView` / `IslandWindowController` 都要过一遍。

跑之前先起 app：

```sh
xcodebuild -project NotchAgent/NotchAgent.xcodeproj -scheme NotchAgent -configuration Debug build
open ~/Library/Developer/Xcode/DerivedData/NotchAgent-*/Build/Products/Debug/NotchAgent.app
```

想直接开在某个形态：`--args -debugState running|notice|expanded|newtask`。
其余状态跃迁走**菜单栏图标**里的调试菜单。

> 菜单栏图标长得像一个刘海矩形，在你那排状态图标的**最左边**。
> 注意：第三方状态项在 `CGWindowListCopyWindowInfo` 里由「控制中心」统一合成、
> 报成匿名的 `Item-0`，所以别靠窗口列表找它——要开关 app 数个数。

## 1. 窗口层级与命中

岛的画布是**这块屏幕上岛能达到的最大尺寸**的透明窗口（本机约 1352×835），压在屏幕顶部中央，
状态切换和拖拽都不改它。岛本身只占其中一小块，**其余全是透明区**。
所以命中测试收回岛的轮廓是**必需的**，不是优化 —— 一旦失效，屏幕上半部的点击会被整片吞掉。

| # | 操作 | 期望 |
|---|---|---|
| 1.1 | 看 idle 态 | 岛比刘海宽出左右各 80pt，上沿两侧内凹拐角、底部圆角。**四周不该有任何描边或黑雾**——岛的边缘和桌面之间是硬边界 |
| 1.2 | **idle 态下**，点岛正下方的桌面／窗口（大约屏幕正中偏上那片） | 点击**穿透**，落到下面的 app 上。这块是透明画布，绝不能吞点击 |
| 1.3 | **idle 态下**，点菜单栏最左边的「NotchAgent / 文件」等菜单 | 菜单正常打开。岛 345pt 宽，左边缘在 583pt，盖不到那里 |
| 1.4 | 展开态下点菜单栏 | 岛此时 560pt 宽，**会**盖住中间那段菜单栏，这是设计如此。只要没被盖住的部分能点就算过 |
| 1.5 | 点控制中心 / 时钟 | 正常展开 |
| 1.6 | 悬停在岛上 | 只有轻微提亮，**不展开、不预览** |
| 1.7 | 展开态，把窗口挪到岛正后方，观察岛的四周 | 岛外**没有**渐变暗环。曾经有一圈 12pt 投影，落在透明画布上是洗不掉的黑雾 |

## 2. 焦点（spec 11.2 的四个条件）

| # | 操作 | 期望 |
|---|---|---|
| 2.1 | 在别的 app 里打字，然后点岛展开 | 岛拿到焦点、**输入框光标直接就位**，不用再点一下；前一个 app 失焦（和 Spotlight 一样）。`NSApp.activate()` 是异步的，焦点要抢两次才稳 |
| 2.2 | 在展开的岛里打字 | 字进输入框 |
| 2.2b | **点一下输入框、tab 芯片、模式芯片、✕** | 全都有反应。拖拽手柄那层是盖在整个岛上的，若没显式放行点击会把这些全挡掉，表现和「光标没激活」难以区分 |
| 2.3 | 切中文输入法打字 | 候选框浮在岛**之上**，不被挡 |
| 2.4 | 按 Esc | 新建流程中先取消新建；再按一次收起岛，焦点回到 2.1 里那个 app |
| 2.5 | idle / running / notice 三态 | 全程不抢焦点，别的 app 打字不受影响 |

## 3. 屏幕几何

| # | 操作 | 期望 |
|---|---|---|
| 3.1 | 插上外接显示器 | 岛留在内置屏（主屏）上，不复制到外接屏 |
| 3.2 | 把菜单栏拖到外接屏（外接屏成主屏） | 岛跟过去，无刘海所以内凹拐角为 0，呈屏幕顶部居中浮条 |
| 3.3 | 拔掉外接屏 | 岛回内置屏，内凹拐角恢复 |
| 3.4 | 改分辨率（缩放档位） | 岛重新测量，宽高跟着变，仍贴齐上沿 |
| 3.5 | 合盖睡眠再唤醒 | 岛还在且位置正确 |

## 4. Space 与全屏

进出全屏、切 Space 都有约一秒动画，通知到达时窗口尺寸还没稳定。
任何环境变动之后都会每 0.5 秒复查一次、持续 3 秒，藏起来期间则一直复查。
所以「该消失的没消失 / 该回来的没回来」最多等一秒，**超过就是 bug**。

| # | 操作 | 期望 |
|---|---|---|
| 4.1 | 切到另一个（非全屏）Space | 岛跟随，每个 Space 都在 |
| 4.2 | 把某个 app 切全屏 | 岛消失（刘海区被系统占用，spec 3.4）。**只有全屏才消失**，普通最大化不算 |
| 4.3 | 退出全屏 | 岛在一秒内自己回来，不需要点任何地方 |
| 4.4 | 全屏 app 与普通 Space 之间来回切 | 岛跟着消失/恢复，不残留 |
| 4.5 | **把岛展开着**，再切到全屏 app 的 Space | 岛**先收起再消失**。展开态是抢着焦点的，只 orderOut 会留下一个看不见却仍是 key 的窗口，键盘继续进岛 |
| 4.6 | 从全屏 Space 切回来 | 岛以收起态回来（不会替你恢复成展开），焦点在你原来那个 app 上 |

## 5. 四态与动画

| # | 操作 | 期望 |
|---|---|---|
| 5.0 | 一个会话都没有时点开岛 | 直接落在新建流程：项目列表（读 `~/.claude/projects/`）+ 指令框，光标就位 |
| 5.1 | 选一个项目、敲指令回车 | 生成一个新 tab（第 1 阶段是假会话），岛进入 running |
| 5.2 | 点 tab 条末尾的 ＋ | 回到新建流程 |
| 5.3 | 调试菜单「新建假会话」两次 | 仍是 running，状态带显示选中的那个 |
| 5.4 | 「完成最早的会话」 | → notice，弹出 tab 条，完成的 tab 图标带绿色对勾角标 |
| 5.5 | 不动它 | notice **常驻**，不自动收起 |
| 5.6 | 再「完成最早的会话」 | 仍是 notice，两个 tab 都带对勾 |
| 5.7 | 点 notice 上的某个 tab | → expanded，该 tab 的对勾消失 |
| 5.8 | 点 ✕ 收起，此时还有别的未读 | 回落到 notice，不是 idle |

| 5.12 | 四态之间来回切 | 宽、高、圆角同时插值，内凹拐角全程与主体连续、无缝隙毛边 |

## 6. 状态带（左右分区与状态形态）

状态带最容易出的两类错：文字跑进物理刘海底下，和折成两行。

| # | 操作 | 期望 |
|---|---|---|
| 6.1 | 一个会话都没有时看 idle | 左侧只有 `NotchAgent` 一行，**不折行**；右侧空 |
| 6.2 | 新建两个假会话 | 左侧：状态点 + 会话名（超长截断成 `refactor-a…`）；右侧：本轮计时 + 会话数 |
| 6.3 | 盯住左右两侧的文字边界 | 左侧文字**在刘海左边缘之前就结束**，右侧文字**在刘海右边缘之后才开始**。任何一侧压到刘海底下都是 bug |
| 6.4 | 让计时跑一会儿 | 每秒跳一次；过一小时补上小时位 |
| 6.5 | 看「在跑」的状态点 | 琥珀色，约 1.1 秒一次**慢呼吸** |
| 6.6 | 调试菜单「最早的会话开始问你」 | 该会话转「等你回话」：状态点变**蓝色、约 0.55 秒一次快闪**，tab 角标变蓝色问号，岛进入 `notice` |
| 6.7 | 再「完成最早的会话」 | 绿色、不闪 |
| 6.8 | 「清空会话」后看 idle | 回到 6.1 |

| # | 操作 | 期望 |
|---|---|---|
| 7.1 | 展开一个 CLI 会话 | 输入框上方一行：`ctx / 5h / 周` 三条额度 + 百分比，右侧子代理数与模式芯片 |
| 7.2 | 点模式芯片 | 在 `Manual → Accept edits → Plan → Auto` 之间轮换；非 Manual 档位显示为蓝色。**档位名要和你在终端里 ⇧Tab 看到的选单逐字一致** |
| 7.3 | 按 ⇧Tab | 与点击效果相同 |

| 7.6 | 点停止 | 该会话转完成、岛**保持展开**、tab 上**不出现**未读对勾（自己按的停止不该再催你） |

## 8. 拖拽调整尺寸（展开态）

拖动时**承载岛的窗口一动不动**（它一开就是最大尺寸），只有岛在里面变形。
所以任何闪烁、抖动、岛偏离屏幕中线，都是 bug。

| # | 操作 | 期望 |
|---|---|---|
| 8.1 | 展开后看边缘 | 底边中央一条短横条，两个下角各一个折角标记 |
| 8.1b | **直接按住那个折角标记往外拖** | 照常缩放。装饰画在手柄之上，若没显式放行点击，角落反而会变成唯一拖不动的地方 |
| 8.2 | 鼠标扫过**左右两条竖边** | 光标变左右箭头。这里必须有反应 —— 调整窗口的直觉就是抓侧边 |
| 8.3 | 鼠标移到底边中段 / 两个下角 | 分别变上下箭头 / 斜向箭头（macOS 15+）。**移开后光标必须变回来**，卡住不还原是 bug |
| 8.4 | 拖左侧竖边往左 | 岛左右**对称**变宽，高度不变 |
| 8.5 | 拖底边中段往下 | 只有内容区变高，tab 条 / 用量条 / 输入框高度不变 |
| 8.6 | 拖右下角往右下 | 同时变宽变高 |
| 8.7 | 快速来回猛拖任意手柄 | **全程不闪、不抖**，岛始终跟手 |
| 8.8 | 拖右下角往右拖到底，再拖左下角往左拖到底 | 岛**始终居中于屏幕中线**，绝不会整块跑偏。宽度停在上限 |
| 8.9 | 一直往里拖到底 | 停在下限（宽 420pt），内容仍排得下 |
| 8.10 | 收起再展开 | 记住刚才拖出来的尺寸 |

> 第 1 阶段尺寸只活在内存里，重启 app 会回到默认 —— 持久化在第 2 阶段随 tab 一起写 Application Support。

## 9. 对照视觉定稿

间距、字号、圆角、状态点颜色、tab 选中态的底色与顶部高光。

**已知偏离**：
- 正在跑的 tab，定稿用一个黄点顶替身份图标，实现改成了「图标常在、状态挂角标」。
- 定稿没有用量条、没有「等你回话」状态、没有拖拽手柄，这三样是定稿之后加的。
